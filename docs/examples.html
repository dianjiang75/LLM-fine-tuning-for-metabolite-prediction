Uses the same prompt and trained generator as configuration 2. Each of the 17 rule-generated candidates is scored by mean log probability across its completion tokens, including the closing tag. Higher scores rank first.

How the score is calculated

The supplied completion is split into tokens. For each token, the model evaluates its probability given the prompt and the earlier completion tokens. The API returns the natural logarithm of that probability.

ℓᵢ = ln P(token i | prompt, earlier completion tokens)
score = (ℓ₁ + ℓ₂ + … + ℓₙ) / n

Python averages the returned completion log probabilities. The closing </metabolite> tag contributes tokens to this average. Prompt tokens and an end-of-sequence token are excluded. A higher score, closer to zero, ranks first.

Worked arithmetic and the scoring code

Illustrative values for a hypothetical three-token completion.

Token probabilities:       0.80,   0.50,   0.25
Natural log probabilities: −0.223, −0.693, −1.386
Mean log probability: (−0.223 − 0.693 − 1.386) / 3 ≈ −0.768

The prompt and completion are tokenized separately and concatenated. The scoring code then takes the completion entries from the API result:

tail = [x for x in fut.result()[-n_completion:] if x is not None]
score = float(np.mean(tail)) if tail else -1e9

Here, n is the number of returned completion entries after missing values are removed. The fallback score is used if there are no usable entries.

The prompt above uses the first-ranked candidate. The ranker evaluates all 17 rule-generated candidates individually using log P(yes) − log P(no). Higher scores rank first.

How the score is calculated

The model evaluates the next-token probabilities of “yes” and “no” after the same parent–candidate prompt. Each verdict is one token. The API returns their natural log probabilities, and Python subtracts them:

score = ln P(yes | prompt) − ln P(no | prompt)
      = ln [P(yes | prompt) / P(no | prompt)]

A positive score means “yes” has greater probability than “no”. A negative score means “no” has greater probability. Candidates are sorted by descending score. These scores have not been calibrated as biological probabilities.

Worked arithmetic and the scoring code

Illustrative values for one hypothetical candidate.

P(yes | prompt) = 0.80     ln P(yes | prompt) ≈ −0.223
P(no  | prompt) = 0.10     ln P(no  | prompt) ≈ −2.303
score = −0.223 − (−2.303) ≈ 2.08
      = ln(0.80 / 0.10) = ln(8)

In this illustration, “yes” is eight times as probable as “no”. The probabilities come from the full token vocabulary, so other tokens can carry some probability too.

The scoring code uses only the final token entry from each API result:

score = float(f_yes.result()[-1]) - float(f_no.result()[-1])
