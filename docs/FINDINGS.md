Results from different scoring passes are identified where they differ.

## 0.5 Which split every number comes from

Three disjoint splits, checked on standardised parent keys in `notebooks/02`:

| split | pairs | parents | what it decides |
|---|---:|---:|---|
| train | 4,276 (17,075 rows after spelling augmentation) | 2,312 | fits the LoRA weights |
| dev, which is the validation split | 437 | 250 | the checkpoint, and recipe comparisons |
| supplied test benchmark | 309 | 155 | arm comparison and exploratory error analysis; inspected during rule development |

**The probe is a fixed subset of dev used for checkpoint selection.** Selection uses 60 parent
strings for the generator and 40 for the ranker because scoring the full dev set at each checkpoint
would dominate runtime. Dev observations below describe selection and training behavior. The
headline arm metrics use the supplied test benchmark.

Test parents are excluded from weight fitting and checkpoint selection. Rule development inspected
test misses, and subsequent experiments use that cohort for error analysis. The final pipeline’s
results are therefore exploratory. A new evaluation cohort must be reserved before further tuning.
Parent counts in this section refer to canonical strings; identity checks use standardised keys.

The following generator measurements also differ in population or sampling budget:

| comparison | matched on | recall@5 |
|---|---|---:|
| the 60-molecule probe the checkpoint was selected on | 8 samples per molecule | 28.6% |
| the 190 dev molecules the probe never saw | 8 samples per molecule | **25.1%** |
| all 250 dev molecules, real decoding policy | 64 samples per molecule | 29.3% |
| the holdout test set, real decoding policy | 64 samples per molecule | **21.4%** |

**The selected probe scores 3.5 points above the other dev subset.** Both use eight samples per
parent. The subsets differ in their molecules as well as their use during selection. The gap
therefore combines selection effects, subset difficulty, and sampling variability. The full-dev
and test measurements share the 64-sample policy and differ by 7.9 points.

29.3% and 25.1% also differ in sampling budget, so their 4.2-point gap does not isolate selection
bias. These observations motivate separate validation and a fixed final evaluation protocol.

**The ranker's 48.5% was used for checkpoint selection.** The probe has 40 molecules carrying
68 pairs, so one pair changes recall by **1.47 points**. Each ranker run evaluated nine
checkpoints and selected its maximum. The probe and test scores therefore differ in both
population and selection history.

Treating pairs as independent gives approximate standard errors of **6.1 points** on the probe
and 2.8 on the test set. Pairs from a drug share one candidate list, so the uncertainty calculation
should instead resample whole drugs. For the cached test baseline, the audit's parent-cluster
bootstrap gives a standard error of 3.07 points and a 95% interval of [40.99%, 53.06%], conditional
on the saved predictions. Section 18 reports the paired interval for the selected SOM prior.

| Top 5 | GLORYx | 64.6 | 16.6 | **30.2** |
| Top 5 | SyGMa | 72.3 | 23.4 | 42.4 |
| Top 10 | MetaTrans | 95.4 | 15.0 | 57.5 |
| Top 10 | SyGMa | 87.7 | 16.2 | **58.7** |
| Top 13 | SyGMa / BioTransformer | 89.2 / 87.7 | 13.6 / 13.5 | **64.2** |

| Top 20 | GLORYx | 92.3 | 10.5 | **73.7** |
| Top 20 | MetaTrans | 96.9 | 8.7 | 64.8 |

- **MetaTrans has no top-1 number.** 42.5% is its *top-5*. The 30.2% sometimes paired with it is
  **GLORYx's** top-5 from the row below.
- SyGMa has higher reported recall than MetaTrans at top-10, top-13 and top-20.
  GLORYx has higher reported recall at top-20.
- MetaTrans already reports precision, falling from 23.5% at top-5 to 8.7% at top-20.
- "At least one metabolite" is 80.0% where recall is 42.5%, so per-parent and per-pair views of the
  same predictions differ by ~38 points.

**Matching implementation.** MetaTrans's released `get_similarity` implementation uses
`Chem.RDKFingerprint`. The first version of this project's comparison used Morgan fingerprints
with radius 2 and 2,048 bits. Its 44.7% recall and 60.6% parent hit rate used that different
criterion. The audit confirmed that the two fingerprint methods disagree on four reference rows
when applied to the same cached top five: 142/309 hits with RDK fingerprints and 138/309 with
Morgan fingerprints. The corrected comparison uses RDK fingerprints and reports **46.0% recall,
18.2% precision, and 61.3% of parent strings with at least one hit** for this later cache.
`python scripts/rescore_saved.py --write` regenerates these values in
`docs/published_comparison.csv` from `SOM/som_candidate_scores.json` and the supplied test data.

Source implementation: [MetaTrans `utils.py`, `get_similarity`](https://github.com/KavrakiLab/MetaTrans/blob/master/utils.py#L194).

The cited Table 4 uses **65 drugs and 179 metabolites**, with an approximately five-product output
(324 predictions across those drugs for the MetaTrans setting). Our supplied cohort has **155
canonical parent strings and 309 pairs**, and uses a fixed five-slot denominator. The supplied
datasets also differ from the originals. A
`source = MetaTrans` field identifies provenance without establishing cohort equivalence.

The published values provide context. Competitive conclusions require matched populations,
reference sets, output policies, and a reproduced matching implementation. The MetaTrans model
was not run here. Source: [Litsa, Das & Kavraki, Chem. Sci. 2020, §3.3/Table 4](https://pubs.rsc.org/en/content/articlehtml/2020/sc/d0sc02639e).

## 2. The provided metric has a hard ceiling

309 test rows over **155 unique parents**. One parent receives one list of k predictions, scored
separately against each of its rows, so a parent's rows can only be satisfied k answers at a time.

The ceiling depends on which match criterion is used, because a looser criterion merges some of a
parent's metabolites and lets one prediction satisfy several rows at once.

| k | Ceiling under **exact canonical SMILES** | Ceiling under **standardized** |
|---:|---:|---:|
| 1 | **0.502** | 0.515 |
| 3 | 0.851 | 0.864 |
| 5 | 0.958 | 0.964 |
| 10 | 1.000 | 1.000 |

Ceilings and recall values should identify the matching criterion. The evaluation output includes
absolute recall and its fraction of the corresponding ceiling.

Metabolites per test parent: 83 parents have 1, 36 have 2, 17 have 3, 5 have 4, 7 have 5, 4 have 6,
2 have 7, and one has 10. Mean 1.99.

## 4. Leakage audit

| Check | Result |
|---|---|
| Exact parent SMILES, train vs test | **0 / 155 (0%)** |
| Canonical parent, train vs test | **0 / 155 (0%)** |
| Canonical parent, GOSTAR vs test | 0 / 155 (0%) |
| **Standardised parent, GOSTAR vs test** | **1 / 155** |
| Exact (parent, metabolite) pair, GOSTAR vs test | 0 / 309 (0%) |
| **Standardised pair, GOSTAR vs test** | **1 / 309, see below** |
| **Distinct parent Bemis-Murcko scaffold types, primary sources vs test** | **44 / 101 (43.6%)** |
| Test metabolite appears as a train metabolite | 21 / 302 (7.0%) |
| Test metabolite appears anywhere in train | 43 / 309 (13.9%) |

The three primary files share no parent and no pair with the test set, under both notions of
sameness.

Under the standardised key the scorer uses, **one raw GOSTAR pair duplicates a test pair**:
nafamostat to 4-guanidinobenzoic acid. Canonical-SMILES equality misses this overlap.

**A leakage check has to use the same notion of sameness as the scorer**, or it misses precisely
the cases the scorer will count as correct. A train/dev split grouped on raw SMILES made the same
mistake and leaked a fifth of the development set (99 of 486 dev pairs, notebook 02 section 4).

The GOSTAR training pipeline excludes this parent and all development-parent overlaps.

The 44/101 scaffold overlap counts distinct scaffold types. It corresponds to 88/155 test parent
strings under the supplied scaffold column. This exposure and the metabolite-side overlap
motivate a similarity-stratified analysis; their effect on performance requires measurement.

## 5. No-model baselines

| Baseline | top-1 | top-5 | top-10 | top-1 Tanimoto |
|---|---:|---:|---:|---:|
| Predict the parent unchanged | 0.00% | n/a | n/a | **0.634** |
| Nearest train parent, copy its metabolites (exact match) | 0.97% | 4.21% | 5.83% | n/a |
| Ten most frequent train metabolites | 0.00% | 0.00% | 0.00% | n/a |

**Predicting the unchanged parent scores 0.634 mean Tanimoto and zero exact-match recall.**
Similarity scores should be interpreted alongside this baseline. The provided Morgan fingerprint
is chirality-blind by default.

The following paired comparison uses the **122 test
parents** where the rule set reproduces a true metabolite and also yields at least two wrong
candidates, everything standardised before fingerprinting:

| Prediction | Tanimoto to the truth |
|---|---:|
| the correct molecule | 1.000 |
| the best **wrong-site** candidate | **0.715** |
| the parent, unchanged | **0.692** |

The paired difference is **+0.023, 95% bootstrap interval [+0.009, +0.038]**. For 48 of the 122
parents, the unchanged parent has higher similarity than every unmatched candidate. The average
difference provides limited guidance for judging an individual prediction.

The 0.634 whole-test-set figure above averages 309 pairs. The paired comparison uses 122 parents,
so the two summaries describe different populations.

Across the checked candidate lists for all 155 parents, the highest similarity of an unmatched
candidate is **0.893**. A standardized match scores 1.000. Cutoffs from 0.90 to 0.99 therefore
produce the same decisions in this candidate set. This observation is specific to these molecules;
fingerprint collisions can occur elsewhere (§15).

Tanimoto is reported as a diagnostic alongside structure-based recall.

**The nearest-neighbor copying baseline scores 4.2% exact recall@5 and 5.5% standardized.**
Higher model scores outperform this particular retrieval procedure. They do not exclude other
forms of memorization or learning by analogy.

Per-parent versus per-pair diverge immediately: at k=5 the nearest-neighbour baseline gives 4.21%
per-pair, 5.75% per-parent mean, 7.74% per-parent hit rate (exact match).

## 8. Stereochemistry changes the matching endpoint

| | Test | Train (deduped) |
|---|---:|---:|
| Metabolites carrying stereochemistry | 42.4% | 35.2% |
| Metabolites gaining a stereocentre vs parent | 28.8% | 38.8% |
| **Unique pairs collapsed by stripping stereo** | **5 / 309 (1.6%)** | **1,171 / 5,679 (20.6%)** |

- Removing stereo merges five test rows and changes the top-1 capacity ceiling from 0.5016 to
  0.5146. This duplicate-row count does not quantify its effect on model predictions.
- Under this identity policy, 1,171 training pairs collapse with another stereo form.
- **22.6% of distinct training skeletons (905 of 4,010) are recorded with more than one stereo
  form.** Different enzymes and conditions can produce different forms. Their occurrence does
  not establish that stereochemistry is biologically uninformative.

The headline criterion describes connectivity after normalisation, charge neutralisation,
canonical tautomer selection, and removal of stereo. Re-scoring the same cached ranker top five
from `SOM/som_candidate_scores.json` gives 104/309 (33.7%) under exact canonical matching,
138/309 (44.7%) with stereo removed, and 145/309 (46.9%) under full standardisation. This cache
belongs to the prior experiment and differs by one hit from the original 46.6% ranker result.
Endpoint choice materially changes measured performance; `evaluate_all_criteria` exposes that
sensitivity. A standardized match establishes agreement under this identity policy, including
cases where specified stereochemistry differs. It does not establish the full stereochemical
structure of a metabolite.

Recall@5 measures recovery of recorded references. The datasets may omit real metabolites, so
the measure cannot estimate recall over all products formed in the body. `precision_known` treats
unrecorded products as unmatched and is a lower bound on biological precision, assuming the
reference annotations themselves are correct.

## 9. Tautomer representation is inconsistent in the source data

Measured on a 1,200-pair sample: **58.2% of parents and 23.8% of metabolites change** under RDKit
tautomer canonicalisation. Several apparent missing reactions were the same molecule written as
`C(O)=N` on one side and `C(=O)N` on the other.

Standardized comparisons apply one `standardize()` function to both operands: normalise functional
groups, neutralise charges, select a canonical tautomer, and drop stereochemistry. Generator
training targets are canonical, stereo-stripped SMILES; full standardization is applied when
constructing identity keys and comparing targets, predictions, and references.

Matching on the first block of the standard InChIKey is a faster alternative. On the full test set
it gives **identical coverage (72.2%) and agrees on all 309 pairs**, at roughly 80x the speed.
The pipeline retains standardization for consistency with its training-label and evaluation keys.
Caching avoids repeated work in enumeration loops.

| Case | Plain canonical SMILES | Standardized |
|---|---|---|
| amide vs imidic acid | no | **yes** |
| lactam vs lactim | no | **yes** |
| 2-pyridone vs 2-hydroxypyridine | no | **yes** |
| charged vs neutral carboxylate | no | **yes** |
| keto vs enol | no | **yes** |

Full standardization increases measured coverage by **3.6 percentage points** over
stereo-stripped canonical-SMILES matching.

## 10. Rule set

| Test coverage ceiling | v1 (20 rules) | **v2 (42 rules)** |
|---|---:|---:|
| Exact canonical SMILES, stereo included | 43.0% | **53.7%** |
| Canonical SMILES, stereo stripped | 56.0% | **68.6%** |
| Standardized | n/a | **72.2%** |
| Candidates per parent (median) | 19 | **32** |

Training coverage: **52.9% to 67.5%**.

The v1 measurements are retained from the original experiment record. The first tracked rule CSV
already contains 42 rules, so the 20-rule version cannot be regenerated from the repository.

### Changes between the rule sets

1. **Generalising dealkylation from methyl-only to any alkyl.** v1 used `[#7:1][CH3]`.
   Within the affected groups v1 reached only 16.8% (`C-2 H-4`, N/O-deethylation) and 12.5%
   (`C-3 H-6`, deisopropylation). Phenacetin to paracetamol was unreachable. v2 breaks the N-C or
   O-C bond generically and keeps the larger fragment: 396 and 349 training pairs explained.
2. **Standardising every molecule before comparison** (section 9).
3. **Added phase II and hydrolysis chemistry**: glycine, taurine, glutamine, GSH, phosphorylation,
   carbamate and ester hydrolysis, epoxidation, azo and nitro reduction.

### Per-rule cap check

Coverage at per-rule caps of 60, 200 and uncapped is identical across the four largest miss groups
checked. Increasing the cap did not recover those references.

### Per-rule positive control

Seven rules received no matched-pair attribution in the combined run. Each produces matching
products when run in isolation; another rule receives attribution first in the combined run.
Counts below come from a larger run than the 200-pair sample in notebook 01 section 6.
These checks establish that a rule can reproduce recorded products. They do not validate every
product the rule can generate (§21).

| Rule | Fires on | Explains alone |
|---|---:|---:|
| acid glucuronidation | 695 parents | 83 pairs |
| ester hydrolysis | 565 | 76 |
| primary alcohol to acid | 376 | 49 |
| carbamate hydrolysis | 77 | 9 |
| N-dealkylation (ring opening) | 1,258 | 2 |
| taurine conjugation | 695 | 1 |
| glutamine conjugation | 695 | 1 |

Zero attribution in a combined run is therefore insufficient evidence for deleting a rule.

### Remaining misses

| | |
|---|---:|
| Still missed | 86 / 309 (27.8%) |
| Distinct reaction types among misses | **60** |
| Types appearing exactly once | **50** (83% of types, 58% of misses) |
| Largest remaining group | `O+1`, 11 pairs (3.6% of test) |

The stopping decision used these test misses. Test parents were excluded from weight fitting.
The complete prediction pipeline was developed with access to the test distribution. Its
results are exploratory, and a fresh cohort is required for an independent final evaluation.
The saved record does not identify the resulting optimism in percentage points.

The 86 misses grouped by the formula change from parent to metabolite, **including hydrogen**:

| transformation | pairs | share of test | coverage if recovered |
|---|---:|---:|---:|
| `O+1` (one oxygen added) | 11 | 3.6% | 75.7% |
| `C-1H-2` | 5 | 1.6% | 77.3% |
| `H-2` (a dehydrogenation) | 4 | 1.3% | 78.6% |
| true isomerisation (no formula change) | 3 | 1.0% | 79.6% |
| `H-2O+1` | 3 | 1.0% | 80.6% |
| *(55 further transformations)* | 60 | 19.4% | 100% |

The five largest families contain 26 references, or **8.4 points** of possible coverage.
Recovering them would require rules that produce the recorded structures at the appropriate sites.

**Grouping must count hydrogen.** RDKit's `GetAtoms()` does not count implicit hydrogens, so
acetaminophen to NAPQI looks like an isomerisation when the change is `H-2`, an oxidation. Grouped
without hydrogen, six of the nine apparent "isomerisations" were hydrogen changes, and merging
them inflated the head of the distribution from 8.4 points to 12.

**Coverage and ranking are evaluated together.** Overall recall factors as coverage times
conditional recall. Holding conditional recall fixed would translate a point of coverage into
0.43 points of recall for arm 4 or 0.64 for arm 6. Adding candidates can change conditional recall,
so these factors are conditional planning assumptions. Returns from new rules require measurement.

Arm 5 (§13) pooled rule candidates with generated candidates. It increased coverage and reduced
recall by 8.4 points.

### Stereochemistry

Removing stereochemistry increases rule coverage by **14.9 percentage points** (12.9 under v1):
the gap between the exact and stereo-stripped rows above. Some conjugation templates specify
stereochemistry that conflicts with the reference annotations. Standardized matching merges
these forms, so headline recall measures normalized connectivity recovery. Section 8 gives the
corresponding sensitivity for the ranker's saved predictions.

## 12. The fine-tune

Qwen3-8B, LoRA rank 32 on all weight matrices, batch 48, learning rate 1e-4, six epochs over
17,075 written examples. 2,130 training steps plus the 20-step smoke run, so 2,150 optimizer
updates. The checkpoint paths are recorded in `data/processed/finetune_run.json`.

**The generator experiments were run twice.** Numbers below are the second run shown in the
notebook outputs; selected first-run values appear as *(replicate: x)*. Two runs provide a limited
check of repeatability and do not support a reliable training-run variance estimate. The later
direct-ranking comparison used one training run per data mixture (§16).

Measured on dev, with the untuned model given **the same molecules, the same bare prompt, the same
decoder and the same k**, so the only difference is the training:

| | recall@5 | recall@1 |
|---|---|---|
| untuned, same prompt and decoder | 0.0% *(replicate: 1.0%)* | 0.0% |
| fine-tuned, all 250 dev molecules, real decoder | **29.3%** *(replicate: 29.5%)* | 16.0% |

29.3% is 30% of the metric ceiling at k=5. Best checkpoint at step 1416 *(replicate: 1652)*.

### Selecting on dev loss

Dev loss uses the same tokenisation as training loss (§15), recomputed over the 20 saved
checkpoints. The mis-tokenised variant differs by 0.006 on average, its minimum is also at step
354, and the cost of selecting on loss is 9.2 points either way. Both series are in
`data/processed/finetune_history.csv` as `dev_loss` and `dev_loss_defective`; the figures and
numbers below use `dev_loss`.

The untuned reference was re-measured the same way, over the same 160 examples: **1.496**, against
the 0.947 the defective protocol reported. That shift, 0.549, is far larger than the 0.006 the
trained checkpoints moved, because the defect dropped the EOS position and mis-sliced the answer
boundary, and an untuned model is at its worst exactly there. Both figures are in
`finetune_run.json` as `untuned_dev_loss` and `untuned_dev_loss_defective`.

| | step | dev loss | recall@5 |
|---|---|---|---|
| dev loss minimum | 354 (epoch 0) | **0.2603** | 19.4% |
| recall@5 maximum | 1416 (epoch 3) | 0.3247 | **28.6%** |
| last step | 2129 (epoch 5) | 0.3625 | 25.5% |

Both curves are drawn on one step axis in `docs/finetune_curves.png`.

Training loss over the same span fell 0.670 → 0.066, and dev loss rose after step 354, suggesting
overfitting to the recorded answer strings. Recall@5 continued to improve on the probe for three
more epochs. **The dev loss minimum landed on step 354 in both runs**. The recall difference
between the loss-selected and recall-selected checkpoints was 9.2 points here and 7.1 in the
replicate.

Cross-entropy measures the probability assigned to each recorded answer string. Recall@5 measures
whether a prediction matches the reference under standardized identity. Alternative metabolite
answers and equivalent SMILES spellings can affect these objectives differently. That is one
possible explanation for the divergent curves; the experiment did not isolate its contribution.

These runs show a mismatch between the loss and the task metric. The 9.2-point difference is on
the dev selection probe; a predeclared holdout comparison of checkpoint-selection policies was
not run. Keep dev loss as a diagnostic and choose a selection metric aligned with the intended
output task.

### The selected probe and other dev parents differ

The checkpoint is chosen on a 60-parent probe and then measured on the other 190 dev parent
strings. The observed gaps were +3.5 points here and −0.9 in the recorded replicate. Both
measurements combine subset difficulty, selection, and stochastic sampling. Neither isolates a
selection penalty or bounds it. Use fresh validation measurements and preserve the underlying
predictions to estimate selection effects more carefully.

### Output-format errors decrease early in training

The untuned model on the same prompt returns an unreadable reply for **29.8%** of samples and
echoes its input unchanged for **32.5%**. Both collapse to roughly 10% inside the first epoch,
while recall@5 continues to increase on the probe. On the test set, the bare-prompt untuned arm
(1b) returned an unreadable reply for 47.3% of samples under the original parser (notebook 04).
These diagnostics show that improved output validity contributes to the measured gain. Raw
replies were not retained, so the stricter parser introduced in §22 cannot be applied to those
samples retrospectively.

## 14. Direct yes/no ranking supervision

Arm 4 is a model fine-tuned to **write** metabolites, whose generative likelihood is then used to
score rule-enumerated candidates. Its training examples contain recorded metabolites as targets.
Arm 6 trains the same base model on that decision directly: `<parent>P</parent><candidate>C</candidate>`
to `yes` or `no`, 24,025 examples over 1,812 training parents, where the negatives are the other
products of the same 42 rules on the same parent and half of each parent's negatives are its
fingerprint near-misses.

| arm | recall@1 | recall@5 | precision@5 | parents with a hit @5 |
|---|---:|---:|---:|---:|
| 2 Untuned, ranking by likelihood | 6.1% | 20.4% | 8.0% | 34.2% |
| 4 Fine-tuned generative used as ranker | 12.9% | 30.7% | 12.0% | 45.8% |
| 6c Untuned, ranking *(control)* | 2.9% | 16.2% | 6.3% | 26.5% |
| **6 Fine-tuned to rank** | **17.2%** | **46.0%** | **17.9%** | **61.3%** |

### Same-format control

An **untuned** model given the identical yes/no scoring format scores 16.2%, compared with 20.4%
for untuned generative-likelihood ranking. The same-format trained ranker reaches 46.0%, a
29.8-point observed increase. This control supports a training benefit for the ranking recipe.
Comparing arm 6 with arm 4 also changes the training examples, scoring method, and checkpoint
selection. That comparison does not isolate the objective alone.

### Where it sits against the ceiling

A ranking arm can only return candidates the rules produced, so its score factors exactly into
coverage times conditional recall (verified to four decimal places for every ranking arm):

| | overall recall@5 | = coverage | x conditional |
|---|---:|---:|---:|
| random ordering of the same lists | 12.7% | 72.2% | 17.6% |
| arm 2, untuned ranking by likelihood | 20.4% | 72.2% | 28.3% |
| arm 4, fine-tuned generative used as ranker | 30.7% | 72.2% | 42.6% |
| **arm 6, fine-tuned to rank** | **46.0%** | 72.2% | **63.7%** |
| best a k=5 ranker could do | **71.5%** | 72.2% | **99.1%** |

Two test parents each have six distinct reachable answers. A top-five list limits an optimal
ranker to 221 of 309 pairs (71.5%), giving a conditional ceiling of 99.1%.

Coverage is unchanged, and conditional recall increases from 42.6% to 63.7%. The improvement
closes **37%** of arm 4's 40.8-point gap to the candidate-list ceiling. The remaining gap is
25.5 points.

Perfect ranking on today's lists could add 25.5 points. Holding conditional recall fixed while
raising coverage to 100% would add 17.7 points. The latter is a planning calculation; additional
candidates can change conditional recall.

### Checkpoint and scoring

**The selected ranker checkpoint is step 750 of 2,000**, epoch 1.5 of 4. It has the highest
recall among nine recorded probe evaluations. Later checkpoints fluctuate below that value.
This describes the selection trajectory for one run; it does not establish a general stopping
epoch.

**The verdict is a single token.** `yes` and `no` each tokenise to one id and neither merges with
the prompt's final newline, so candidates are scored by `logP(yes) - logP(no)` with no length
normalisation at all. Arm 4 has to divide by token count to stop long candidates being penalised;
arm 6 does not have that failure mode.

### What this does not settle

Arm 5's pooling result (-8.4 points) was measured with the **arm 4** ranker, which is weaker than
the trained one. §19 repeats it with the trained ranker.

## 15. Known defects and their effect on the reported numbers

### Fixed

**The dev loss curve measured a different quantity from the training loss.** `to_datum`
builds a training example as `encode(prompt) + encode(completion)`, concatenating two separate
encodings. `dev_loss` encoded the joined string and then sliced it using the separately-encoded
prompt length. Qwen3 merges across that boundary for **88 of 160** probe rows (55%), and the
completion length is miscounted for **68** (42%), so the slice started mid-token. The docstring
claimed the two were "deliberately the same quantity"; they were not. Fixed to build the sequence
the way training does, including the EOS position training supervises.

The 20 checkpoints were still inside their TTL, so the corrected quantity was measured on the
same weights without retraining (results in §12).

The candidate scorer had the same defect: a prefix encoded separately from the string it is a
prefix of.

**Fingerprint equality depends on the fingerprint implementation.** Zero observed collisions
across 10,036 checked rule candidates cannot establish molecular identity in general. Octane and
nonane are distinct structures with identical Morgan fingerprints under the tested settings.
Standardized identity also merges some tautomers that raw fingerprints separate. Section 1
records the additional correction from Morgan fingerprints to MetaTrans's RDK fingerprints.

**`standardize()` was not invariant to SMILES spelling.** RDKit's tautomer canonicaliser picks
among tied tautomers in input order, so the same molecule written two ways could standardise to
two different strings. For one training target, **19 of 40** random spellings disagreed with the
canonical one. Fixed by canonicalising the atom order before standardising; the same molecule now
gives 0 of 40 disagreements.

**The spelling fix preserves the ranked-candidate results.** Rule candidates come from
`MolToSmiles(canonical=True)`, and all **309** test references standardise identically from their
raw and canonical spellings. Generating arms aggregate votes from raw output strings, so the
earlier behavior could have split votes for one molecule across two keys. Raw generations were
not retained, and the effect on their reported results cannot be recovered.

### Not fixed

**Rule products include small coproducts.** `RunReactants` returns a tuple per match, and the code
applies `largest_fragment` to each member independently, so N-dealkylation of `CCNCC` contributes
both `CCN` and `CC`. 180 of 5,243 test candidates (3.4%) are 4 heavy atoms or fewer.

Keeping only the largest product of each tuple removes 470 candidates and loses two recorded
answers, dropping coverage from
72.17% to 71.52%. Both losses are ester hydrolysis where the *smaller* fragment is the real
metabolite, including procaine to diethylaminoethanol. A narrower fix would drop
chemically trivial leaving groups by identity. That alternative remains untested.

### Site parser and metric defects

**The site parser treated symmetry-equivalent atoms as distinct.** The label is mapped onto the parent through
`CanonicalRankAtoms`, which breaks ties by default, so no two atoms ever share a rank. The
docstring said chemically equivalent atoms would all be returned as sites; the code returned
exactly one, and marking the other end of a symmetric pair read as a different site. Over 13,921
labels, re-spelling the same marked molecule changes the site set for **5.2%** of rows, and
**9.8%** have equivalent atoms the label does not list. Fixed with `breakTies=False`, which
returns symmetry classes, and the site experiment was re-run (§17). This changes the site-label
accuracy calculation. The explicit candidate-list check in §17 found no change to filtered
product lists on this cohort.

**`tanimoto_wrong` is not flat across *every* arm.** It is flat across the four arms that rank the
same candidate lists, 0.567 to 0.584. The tuned writer sits at 0.512 and returns different
molecules entirely. Each arm's average is taken over a different population of failed rows, 165 to 246 of them,
so the comparison is suggestive only.

**The decoder is sound on two points.** It does not accept an unchanged parent or let one molecule
occupy two prediction slots: `collapse` drops the parent by key and aggregates votes in a dict
keyed by molecule, verified directly on both cases. The spelling defect above does not affect the
reported numbers.

## 17. Supplied and predicted sites of metabolism

Every test row carries a site label: the parent SMILES with atom maps on the reacting atoms.
The label marks a **set**: 80.9% of rows mark one atom, 16.5% mark two, and a few mark up to seven.
Attributing a
candidate back to the atoms its rule reacted at requires `GetSubstructMatches(..., uniquify=False)`.
With the default, `RunReactants` returns product tuples for symmetry-equivalent matches that the
match list has collapsed, and sites are attributed to the wrong atoms in 58 of 592 rule firings.
The mapping uses `CanonicalRankAtoms(breakTies=False)`, so chemically equivalent atoms
share a rank (§15, site parser). With all three handled, all 309 labels map onto their parent.

**The symmetry fix preserves candidate lists.** Toggling only `breakTies` changes the filtered
list for **0 of 309 rows**, under both filters below. Two symmetry-equivalent atoms
produce the *same* product, so admitting the second adds no molecule the first did not already
contribute. The fix matters for scoring a site *prediction*, where marking the equivalent atom
would otherwise read as a miss.

What the filter costs, over the 223 reachable pairs:

| filter | candidates kept per pair | reachable answers kept | ceiling |
|---|---:|---:|---:|
| to that metabolite's own site | 3.9 | 207 of 223 | 67.0% |
| to the union of the parent's sites | 8.1 | 209 of 223 | **67.6%** |

The union row is the one every "true sites" number below uses, so a parent's list goes from 33.2
candidates to 8.1 and the filter's own ceiling is 67.6%, below the rules' 72.2%.

### Four conditions, one scorer

The same reranker checkpoint, the same `logP(yes) - logP(no)`, the same k. Only the candidate
list changes. "Reachable" is what each arm's own list can contain, so the conditional column is
the fraction of reachable answers that arm returns.

| | recall@1 | recall@5 | precision@5 | = reachable | x conditional |
|---|---:|---:|---:|---:|---:|
| arm 6, no site information | 18.1% | 46.6% | 18.5% | 72.2% | 64.6% |
| **sites predicted by the model** | 14.2% | **32.4%** | 12.6% | **34.0%** | **95.2%** |
| predicted sites, unfiltered fallback | 14.6% | 33.0% | 12.9% | n/a | n/a |
| true sites, union per parent | 30.1% | 61.2% | 23.9% | 67.6% | 90.5% |
| true site per pair (ceiling) | 48.5% | 65.4% | | | |

`docs/som_comparison.png` splits all 309 references into found, available below the top five,
and removed by the filter.

**The supplied answer-derived site annotations add +14.6 points at k=5 and +12.0 at k=1.**
This oracle diagnostic starts from the expanded ranker at 46.6%. The annotations are inferred from
known answers and may contain errors; deployed predictions must obtain sites independently.

**Predicted-site filtering loses 14.2 points.** A second LoRA adapter was trained to mark the
reacting atom (`SOM/som_predictor.ipynb`, 13,373 pairs, 3 epochs, selected on `any_hit`). Its data
includes the three primary sources and mammalian GOSTAR. The shipped SOM training file contains
7,648 standardised parent identities, compared with 2,067 for generator training; 5,599 SOM
identities are absent from generator training. Both development and test identity overlaps are
zero. The site adapter therefore uses a broader training population.

An untuned Qwen3-8B
scores 0.0% and produces a parseable marked molecule only 15% of the time, while the tuned
adapter reaches **70.0%** `any_hit` on the dev probe and **62.6%** on the holdout parents, with
86.1% usable replies and no parent left without a site.

Filtering removes many recorded answers:

- Each reference needs the site that produced that particular metabolite to survive filtering.
  Per-parent `any_hit` of 62.6% corresponds to **105 of 223** reachable pairs whose answer survives
  the filter, a 47% keep rate.
- That caps the arm at a **34.0%** ceiling, below the 46.6% the unfiltered pipeline already scores.
  No ranker can recover an answer that is no longer on the list.
- On the lists that survive, the ranker reaches **95.2%** conditional
  recall.

At the observed 95.2% conditional recall, matching 46.6% overall recall would require keeping
approximately 68% of reachable references. This predictor keeps 47%. Per-atom accuracy figures
from other site-prediction studies measure a different quantity and cannot supply that keep rate.

**Hard filtering reduces candidate coverage from 72.2% to 34.0%.** A score feature can preserve
the full list while changing its order. Whether that order improves depends on the quality and
weight of the site signal. The 64.6% and 95.2% conditional recalls use different surviving subsets,
so their gap does not predict a gain from site features. Section 18 tests score-level integration.

**Fallback to the unfiltered list increases recall from 32.4% to 33.0%.** The code activates
fallback when filtering leaves zero candidates. Every parent has at least one predicted site.
Three parents have no rule candidate supported by those sites. Fallback does not restore
answers for parents whose filtered list is nonempty.

### Scoring a per-pair filter

`evaluate` keeps one prediction list per parent and ignores any further lists for the same parent
(the `if parent in ranked` check). That is correct for every other arm and wrong for a per-pair
experiment: 72 of 155 parents carry more than one metabolite, so **154 of 309 rows (50%)** would be
scored against a list filtered for a different metabolite's site. The per-pair row above is
computed row by row instead.

## 18. Site support as a score prior

The predicted-site gate removes many reachable answers (§17). An additive score bonus preserves
every candidate and allows a direct test of uncertain site information:

```
score(candidate) = logP(yes) - logP(no)  +  LAMBDA * [candidate sits at a predicted site]
```

At `LAMBDA = 0`, scores use the expanded ranker alone. Increasing `LAMBDA` raises site-supported
candidates in the ordering while retaining the full list.

**Predicted sites show enrichment on this benchmark.** Over the 223 reachable test pairs,
25.8% of all candidates sit at a predicted site and 47.1% of correct answers do, a lift of 1.83x.
Supplied sites give 3.75x. These aggregate ratios motivate testing the feature; they do not measure
what fraction of useful information the predictor captures or guarantee improved ranking.

**`LAMBDA` is selected on a 60-parent dev probe.** The table also displays the test sweep for
exploratory analysis; only the dev-selected setting supports the selected-prior comparison.
The values below were re-scored from the existing cache with the current decoder by
`scripts/rescore_saved.py`. No model was retrained or called during this re-score.

| LAMBDA | dev recall@5 | holdout recall@1 | holdout recall@5 |
|---:|---:|---:|---:|
| 0 | 56.1% | 18.1% | 46.9% |
| 0.25 | 55.1% | 17.5% | 47.9% |
| 0.5 | 55.1% | 17.5% | 47.6% |
| **0.75** *(chosen)* | **57.1%** | 17.5% | **47.9%** |
| 1.0 | 57.1% | 17.5% | 48.9% |
| 1.5 | 54.1% | 17.2% | 49.2% |
| 2.0 | 51.0% | 17.5% | **50.8%** |
| 3.0 | 49.0% | 16.2% | 47.3% |
| 4.0 | 43.9% | 14.9% | 45.0% |
| 8.0 | 36.7% | 14.6% | 37.9% |
| 1e6 | 36.7% | 14.6% | 37.2% |

**Retaining candidates recovers 4.9 points over the gate.** At `LAMBDA = 1e6`, every site-supported
candidate ranks above every unsupported candidate. Retaining the unsupported candidates below
that group scores **37.2%**, compared with **32.4%** when they are deleted. The model, site
predictions, and supported-candidate ordering are held fixed. The paired parent-cluster 95%
interval for the 4.85-point difference is [2.27, 7.89] points. This saturated prior remains
9.7 points below the matched 46.9% no-site baseline.

**The dev-selected prior has an uncertain gain.** Dev chose `LAMBDA = 0.75`, which scores 47.9%
against this arm’s 46.9% baseline: +0.97 points, or three reference rows. The paired 95% parent-cluster
bootstrap interval is [−0.65, +2.70] points (`docs/paired_bootstrap.json`), conditional on the
fixed saved predictions. It does not include training variation.

**The test sweep is exploratory.** Seven consecutive values, 0.25 through 3.0, sit above
`LAMBDA = 0` on the holdout set, peaking at 50.8%. Adjacent values reorder largely the same lists,
so their results are correlated. Selecting the best value on this cohort would introduce further
test selection. At the dev-selected setting, the prior improves five parent clusters and worsens
two, with an exact paired sign-test **p = 0.45**. The observed +1.0-point gain remains uncertain.
Dev peaks at 0.75 to 1.0 and test at 2.0. A larger validation cohort and independent evaluation
would be needed to assess the reliability of weight selection.

**Recall@1 does not improve at any tested weight.** The observed top-five gains do not extend to
the first prediction.

**Learned site integration remains an open experiment.** A ranker conditioned on predicted sites
could learn how to use them. It needs out-of-fold site predictions during training to reflect
deployment errors, and a comparison with the no-site ranker on the same candidates. The current
prior result leaves its potential benefit unresolved.

**`LAMBDA = 0` scores 46.93% where arm 6 recorded 46.60%.** The results are one pair
apart, with identical candidate lists checked across all 155 parents. Independent scoring
variation was measured in §16. Every row above shares one scoring pass, which controls that
source of variation within the table.

## 19. Pooling, retested with the trained ranker

Arm 5 pooled rule candidates with generated molecules and ranked the union using generative

| arm | recall@1 | recall@5 | reachable | conditional |
|---|---:|---:|---:|---:|
| trained ranker, rules only | 18.1% | **46.9%** | 72.2% | 65.0% |
| trained ranker, pooled with its own guesses | 12.0% | **29.8%** | 75.1% | 39.7% |

**Pooling reduces recall by 17.2 points with the trained ranker.** The original arm 5 lost 8.4

**The pool increases reachability and reduces realized recall.** It reaches 75.1% of test pairs
against the rules' 72.2%. Conditional recall falls from 65.0% to 39.7%. The additional candidates
include new recorded answers and distractors that displace correct rule candidates.

**The explanation remains untested.** All sampled training negatives came from the reaction
rules. A shift in candidate distribution could contribute to the pooling loss. Testing that
explanation would require training with generated negatives and evaluating on a separate cohort.

## 21. Known implementation limitations before further experiments

A subsequent audit identified three reaction branches that produce incorrect products in checked
examples: ring-opening N-dealkylation (`CN1CCCCC1` produces `CCCCNC` and `CCCCCO`), the alcohol
branch of ester hydrolysis (ethyl acetate produces ethane), and carbamate hydrolysis (ethyl
carbamate produces ammonia, formic acid, and ethane). The acid branch of ester hydrolysis still
matches recorded metabolites. These are candidate-generation defects; their presence does not
change how the saved predictions were scored. Correcting the rules requires new candidate lists
and reevaluation, including effects on ranking and reachable references.

The reranker groups positive references by canonical parent string and labels candidates under
standardised identity. An audit of the shipped training file found 180 parent/candidate groups
with both yes/no labels across 408 rows under stereo-stripped keys. Multiple checked examples also
conflict under full standardisation; a complete census under that criterion remains pending.
Choose one task identity policy, pool positive references accordingly, and regenerate negatives
before the next training run. The recorded model and its numerical results remain unchanged.

These limitations are separate
from direct train/test leakage: the shipped training records have no standardized-parent overlap
with test after the implemented exclusions.

## 22. Two scoring defects, found and corrected

**The SMILES parser accepted prose.** `canonical()` and `standardize()` called
`Chem.MolFromSmiles` without parser parameters, so RDKit's `SMILES<whitespace>NAME` form applied
and a refusal parsed as a molecule:

    canonical("I cannot determine this.")   ->  "I"    before
    canonical("I cannot determine this.")   ->  None   after

A reply decoding this way took a prediction slot and counted as valid. This could understate
`invalid_rate` and place elemental iodine in a generating arm's predictions.
`src/inference.py` already set `parseName = False` for app input; `src/evaluation.py` now does the
same, so the two paths agree on what a molecule is.

Scope: generating arms (1, 1b, 3) and any pooled list inheriting their decoded candidates.
Rule-only ranking uses valid enumerated SMILES and is unaffected. The raw generating replies
were not saved, so their rows in `docs/arm_results.csv` cannot be rescored without fresh sampling.
For an unchanged set of raw replies, rejecting an unmatched iodine prediction would free its
slot and could raise recall. A fresh stochastic sampling run can differ for other reasons.

**Ranking broke ties by input order.** `rank_candidates` and `collapse` sorted on score alone, so
tied candidates fell back to insertion order, which is the order the rules enumerated them.
Scores occur in increments close to 1/8, with ties in the saved results. Shuffling one candidate
list 20 times produced 15 different top-five lists before the fix and 1 after. Both functions now
break ties on the molecule key.

The current decoder recovers **145/309 references (46.9%)** from the saved +GOSTAR score cache.
The original scoring pass in `docs/arm_results.csv` recorded 144/309 (46.6%). These are different
scoring passes; that difference cannot be attributed to tie-breaking alone. The prochlorperazine
worked example recovers 0, 2, 2 and 3 of 3 recorded metabolites for arms 1, 3, 4 and 6.

**precision@5 has a ceiling below 1.** Its numerator is capped by a drug's recorded metabolite
count while its denominator is always k, so the attainable maximum on this test set is 37.8% at
k = 5 and 19.6% at k = 10, using the metric's 155 canonical parent strings. `recall_pair` carries
`ceiling` and `pct_of_ceiling` columns for this
reason and `precision_known` carries neither, so the figure is now stated beside the results
table.

The tie-break fix changes the same-rule error count in section 20 from 14 to 13 among the 24
missed aliphatic hydroxylations. One parent's reordered top five no longer contains a product of
that rule. The current cache recovers 145 of 309 references. `docs/build_misses_figure.py`
rebuilds `docs/misses_by_chemistry.png` using the current decoder.
